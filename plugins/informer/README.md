# Informer — часы, дата и погода

Первый прототип для GMIB Plugin API 1.1: часы и погодные слайды с сохранённым
ответом Яндекс Погоды. Плагин автономен: внешние шрифты, картинки и CDN не нужны.
Рабочее название — Informer; общий план развития: [informer-plan.md](../../docs/informer-plan.md).

## Запуск

1. Установите `informer.gmib-plugin` через раздел «Плагины» GMIB и перезапустите GMIB.
   После обновления также нужен перезапуск: новые файлы страницы могут открыться раньше,
   чем загрузится новый backend. В таком состоянии настройки показывают подсказку,
   предпросмотр доступен, а сохранение новых параметров отключено до перезапуска.
2. Откройте настройки Informer. В «Вывод» выберите уже настроенный экран GMIB
   и нажмите «Назначить и запустить». При необходимости включите автозапуск.
3. Для Волгатех используйте 704×192, для часов рядом с рекламой — 320×192.
   Геометрию экранов и отдельного рекламного плеера настраивайте в GMIB.
4. Выберите группу настроек слева: показываются только её поля и общий предпросмотр.
   После настройки нажмите «Применить». Работающий экран получает изменения
   сразу, через realtime; перезапуск для изменения настроек не нужен. Перезапуск
   требуется при обновлении самого backend-кода плагина: текущий загрузчик GMIB
   активирует его один раз при запуске приложения.

Предпросмотр получает реальные размеры экранов GMIB. Если экранов несколько,
выберите нужный в списке над предпросмотром; при одном экране он выбирается автоматически.
Выбор здесь не запускает и не переназначает вывод. Изменение размеров в GMIB
подхватывается автоматически. При отсутствии экранов сначала добавьте экран в GMIB.

В автоматическом макете широкое табло разделяется на область часов (по умолчанию
320 пикселей) и погоду справа. Метеопоказатели постоянно отображаются под часами,
справа — текущая температура и два ближайших периода прогноза, без слайдов.
В компактном макете погода сменяется под часами.
Плагин сам не управляет рекламным плеером и не меняет его размеры.

Часы и дата центрируются в области часов. Часы прижаты к двоеточию справа,
минуты — слева; положение разделителя не меняется вместе с цифрами. Без секунд
двоеточие из двух круглых точек мигает с периодом в одну секунду.

«Смена значений» в оформлении включает переворот по оси X: старое значение
схлопывается, затем новое раскрывается (440 мс). Часы и минуты меняются целыми
парами цифр; так же обновляются дата, температура, прогноз и метеопоказатели.
Первое появление и переключение погодного слайда не запускают этот эффект.
По умолчанию анимация выключена; системное уменьшение движения учитывается.

## Настройки

- Ширина области часов, автоматический/широкий/компактный макет.
- Секунды, локаль и часовой пояс.
- «Дата и время»: в одной строке — «Четверг, 15 июля, 10:12»; в отдельных
  строках — дата сверху, крупные часы снизу. День недели и год не создают
  дополнительных строк.
- Формат даты задаётся отдельными списками: день недели, день, месяц и год.
  Любое поле можно отключить. Если отключены все поля, остаётся только время.
  Названия и порядок компонентов даты зависят от локали; JSON вводить не нужно.
  Старые сохранённые настройки поддерживаются, прежний `dateStyle` раскрывается
  в отдельные поля при открытии настроек.
- В одной строке размер времени связан с размером даты (при стандартном размере
  часов 80 он равен размеру даты). Длинная строка целиком уменьшается до ширины
  области, сохраняя все включённые поля; настройка размера часов меняет пропорцию.
- Шрифт, размер и цвет времени, даты, дня недели и текущей температуры.
- Независимые группы «Погодные условия», «Прогноз» и «Метеопоказатели»
  (ветер, направление, давление и влажность), общие для обоих макетов.
  Размер погодных условий задаётся для основной подписи («Малооблачно»);
  «Ощущается как» составляет 75% от него. В прогнозе размер задаётся для
  периода («Вечер», «Ночь»), температура — 105% этого размера. Шрифт и цвет
  применяются ко всем связанным строкам группы; текущая температура настраивается
  отдельно. Иконка текущей погоды масштабируется вместе с температурой; иконки
  прогноза — вместе с его размером, по центру высоты названия периода и температуры.
  Если строка не помещается в область погоды, она уменьшается целиком
  с сохранением пропорций, без обрезания текста.
  Пока доступны системные семейства без засечек, с засечками и моноширинное;
  точное начертание зависит от ОС. Размеры указаны для высоты 192 пикселя.
- Интенсивность тени, затемнение подложки от 0 до 100% и обводка текста.
- Выбор подложки: текущий градиент или изображения неба из `yandex-weather`.
- Надпись «Яндекс Погода» включается отдельным чекбоксом; по умолчанию скрыта.
- Включение погодных слайдов и длительность показа (3–120 секунд) в компактном режиме.

Автоматическое время суток учитывает положение солнца по координатам и текущему времени,
а также погодное состояние из сохранённого снимка: облачность, дождь, снег или грозу.
День, сумерки и ночь продолжают меняться даже при замороженном прогнозе. Если
координат нет, используется приближённое расписание в выбранном часовом поясе.
Можно выбрать время суток вручную. Подложка и слайды сменяются плавно.
В предпросмотре можно выбрать погодные условия вручную, чтобы проверить подложку
и текущую иконку. «Автоматически» берёт условия из текущего снимка. Этот выбор
не сохраняется в тему и не влияет на действующий вывод. Подпись «Яндекс Погода»
расположена поверх подложки и не меняет размеры погодных блоков.
Градиент остаётся вариантом по умолчанию, в том числе для сохранённых настроек.
Для подложки «Небо» в архив включены девять локальных изображений:
день, сумерки и ночь × ясное небо, переменная облачность и пасмурное небо.
Дождь, снег, град и гроза используют только пасмурный вариант `cloudy`,
без нарисованных поверх картинки осадков или молний. `clear` соответствует ясной
погоде, `partly-cloudy` — `partly`, `cloudy` и `overcast` — `cloudy`.
Для подложек используются только `day`, `dawn`, `night` × `clear`, `partly`, `cloudy`.
Сохранённое значение времени суток `dusk` совместимо с подложкой `dawn`.
Затемнение действует только на подложку; текст, температура и иконки сохраняют яркость.

На слайде подробностей ветер, направление, давление и влажность расположены в одну
строку. Вместо надписей «Ветер», «Давление», «Влажность» используются оригинальные
локальные SVG-иконки из `yandex-weather`; для направления ветра есть поворотная
стрелка, при штиле она скрыта. Давление указано в мм рт.ст. Показатели без данных
пропускаются. Изображения, иконки и выбор подложки автономны и не обращаются к CDN.
Классами подложки управляет JS, а картинки выбирает CSS (`photo day clear`,
`photo night cloudy` и аналогичные сочетания). Исходные материалы перенесены из
`yandex-weather`; его лицензионный текст сохранён в `public/assets/LICENSE-yandex-weather.txt`.

## Темы и перенос настроек

В разделе «Темы» можно сохранить все текущие параметры под именем: компоновку,
часы и дату, оформление, шрифты и размеры, анимацию и настройки погодных слайдов.
Сохраняются и ещё не применённые значения из формы. Каталог из максимум 50 тем
хранится в локальном постоянном хранилище плагина на устройстве GMIB, вместе
с текущими настройками; он доступен после перезапуска и из другого браузера
управления тем же устройством. Название — до 80 символов. Повторное сохранение
с тем же названием заменяет тему.

«Загрузить» заполняет настройки и обновляет предпросмотр. Чтобы применить их
к действующему экрану, нажмите «Применить». Удаление темы не меняет
текущие параметры экрана.

«Экспорт JSON» скачивает текущие параметры из формы с указанным названием.
На другом устройстве выберите этот файл в «Импорт темы из JSON»: тема сохранится
в каталоге и загрузится в предпросмотр. Импорт с существующим названием заменяет
тему. Некорректный файл не меняет тему и текущие параметры. Файл содержит формат
`gmib-informer-theme`, версию `1`, название и проверенные настройки. Допустимый
размер файла — 512 КБ. Фактическая погода, API-ключи, идентификаторы экранов и
запуск вывода не переносятся. Подложки уже включены в плагин; системные шрифты
на разных устройствах могут выглядеть по-разному.

## Источник погоды и кеш

В разделе «Источник погоды» задайте широту и долготу, ключ **Яндекс Informers v2**
и суточный лимит запросов. Координаты расположены в одной строке. Изменения
применяются общей кнопкой «Применить». Используется `/v2/informers`; ключи других
тарифов могут требовать другой API и пока не поддерживаются.

По умолчанию включено «Использовать последний ответ»: плагин показывает текущий
тестовый JSON для координат 56.6333, 47.8908 без обращения к Яндексу. При каждом
успешном реальном запросе последний ответ заменяется новыми проверенными данными.
Он сохраняется в хранилище GMIB, поэтому доступен после перезапуска и обновления
плагина. Импорта снимков и отдельной кнопки однократной загрузки больше нет.

Пока флаг включён, в правом верхнем углу вывода показана цветная надпись
«Тестовый вывод» поверх картинки. После отключения флага и применения настроек
плагин начинает автоматическое обновление. Уже отправленный запрос может завершиться
перед применением флага; новых запросов в этом режиме нет.

Запросы выполняет единственный планировщик backend независимо от числа открытых
экранов и страниц настроек. После запроса он распределяет оставшийся бюджет
равномерно по времени до следующей полуночи по Москве. Минимальный интервал —
минута. Если бюджет исчерпан, обновления ждут сброса. После выключения компьютера
пропущенные обновления не наверстываются: при запуске новый суточный бюджет
распределяется по оставшейся части дня. Вчерашний расход сбрасывается и тогда,
когда компьютер был выключен в момент полуночи.

В настройках видны расход за сегодня, остаток, общий счётчик, время следующего
обновления и сброса. Каждая попытка учитывается **до отправки**, включая ошибки
провайдера и прерванные запросы. Счётчики и расписание сохраняются; переключение
режима, изменение ключа или координат и перезапуск не обнуляют расход. Ошибки
сети и некорректный ответ сохраняют последнюю погоду. При HTTP 401, 403 или 429
следующая попытка откладывается до сброса суток.

Счётчик отражает запросы **этой установки Informer**. Вызовы того же ключа другими
программами или устройствами в него не входят. Укажите бюджет с учётом таких вызовов;
для нескольких установок разделите общий лимит между ними.

Ключ сохраняется локально в хранилище GMIB, передаётся Яндексу только в заголовке,
не возвращается в состояние, предпросмотр, realtime или темы. Пустое поле при
повторном применении сохраняет прежний ключ. Координаты, бюджет и режим источника
также не входят в темы. Хранилище плагина — `informer.v1`; в установочном архиве
персональных ключей и текущих счётчиков нет.

Backend использует существующий Plugin API 1.1. HTTP-маршруты локальные.
NiBUS и дополнительные погодные API остаются следующими этапами.

## Проверка и сборка

```sh
node --test tests/informer*.test.mjs
pnpm validate
pnpm build --plugin informer
```

Команды выполняются из корня репозитория. Архив: `dist/informer.gmib-plugin`.
Тесты проверяют валидацию и миграцию оформления, независимые настройки прогноза
и метеопоказателей, кеш, суточный бюджет, смену московских суток, паузу и
возобновление запросов, ошибки провайдера/хранилища, отсутствие ключа в публичном
состоянии и перезапуск.
Предпросмотр в браузере проверяет макеты; фактическое расположение окон и
читаемость на LED следует проверять на настроенной установке GMIB.

## Приложение настроек на рабочем столе

Откройте страницу настроек Informer на localhost в Chrome или Edge. Нажмите
«Установить приложение», если браузер показывает эту кнопку, либо выберите установку
в меню браузера. Ярлык открывает настройки в отдельном окне.

После первого открытия при работающем GMIB оболочка настроек сохраняется локально.
Если GMIB закрыт, приложение показывает «Запустите GMIB» и автоматически
восстанавливает связь после его запуска. Данные API не кешируются этим приложением:
для чтения и применения настроек GMIB должен работать.

Кнопка «Применить» сохраняет настройки и показывает уведомление «Настройки применены»
после подтверждения от GMIB. При ошибке появляется сообщение с её причиной.
