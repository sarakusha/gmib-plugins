# Informer — часы, дата и погода

Для GMIB 5.7.1 и Plugin API 1.2: часы и погодные слайды с кешем Яндекс Погоды.
Шрифты и подложки локальные; погодные иконки Яндекса имеют встроенную замену при
недоступности сети.
Рабочее название — Informer; общий план развития: [informer-plan.md](../../docs/informer-plan.md).

## Запуск

1. Установите `informer.gmib-plugin` через раздел «Плагины» GMIB и перезапустите GMIB.
   После обновления также нужен перезапуск: новые файлы страницы могут открыться раньше,
   чем загрузится новый backend. В таком состоянии настройки показывают подсказку,
   предпросмотр доступен, а сохранение новых параметров отключено до перезапуска.
2. Откройте настройки Informer. В «Вывод» выберите широкий и компактный экраны GMIB,
   текущий режим и нажмите «Показать». При необходимости включите автозапуск.
3. Для Волгатех используйте 704×192, для часов рядом с рекламой — 320×192.
   Геометрию экранов и отдельного рекламного плеера настраивайте в GMIB.
4. Выберите группу настроек слева: показываются только её поля и общий предпросмотр.
   После настройки нажмите «Применить». Работающий экран получает изменения
   сразу, через realtime; перезапуск для изменения настроек не нужен. Перезапуск
   требуется при обновлении самого backend-кода плагина: текущий загрузчик GMIB
   активирует его один раз при запуске приложения.

Предпросмотр получает реальные размеры экранов GMIB. По умолчанию выбран «Текущий режим»:
при показе и переключении он следует за фактическим экраном вывода. Когда вывод скрыт,
используется экран сохранённого режима. В списке можно выбрать конкретный экран, чтобы
закрепить его в предпросмотре независимо от переключений.
Выбор здесь не запускает и не переназначает вывод. Изменение размеров в GMIB
подхватывается автоматически. При отсутствии экранов сначала добавьте экран в GMIB.

В автоматическом макете широкое табло разделяется на область часов (по умолчанию
320 пикселей) и погоду справа. Метеопоказатели постоянно отображаются под часами,
справа — текущая температура и два ближайших периода прогноза, без слайдов.
В компактном макете погода сменяется под часами.
Плагин сам не управляет рекламным плеером и не меняет его размеры.

Часы и дата центрируются в области часов. Часы прижаты к двоеточию справа,
минуты — слева; положение разделителя не меняется вместе с цифрами. Без секунд
двоеточие из двух круглых точек мигает с периодом в одну секунду.

«Смена значений» в оформлении включает переворот по оси X: старое значение
схлопывается, затем новое раскрывается (440 мс). Часы и минуты меняются целыми
парами цифр; так же обновляются дата, температура, прогноз и метеопоказатели.
Первое появление и переключение погодного слайда не запускают этот эффект.
По умолчанию анимация выключена; системное уменьшение движения учитывается.

## Настройки

- Ширина области часов, автоматический/широкий/компактный макет.
- Секунды, локаль и часовой пояс.
- «Дата и время»: в одной строке — «Четверг, 15 июля, 10:12»; в отдельных
  строках — дата сверху, крупные часы снизу. День недели и год не создают
  дополнительных строк.
- Формат даты задаётся отдельными списками: день недели, день, месяц и год.
  Любое поле можно отключить. Если отключены все поля, остаётся только время.
  Названия и порядок компонентов даты зависят от локали; JSON вводить не нужно.
  Старые сохранённые настройки поддерживаются, прежний `dateStyle` раскрывается
  в отдельные поля при открытии настроек.
- В одной строке размер времени связан с размером даты (при стандартном размере
  часов 80 он равен размеру даты). Длинная строка целиком уменьшается до ширины
  области, сохраняя все включённые поля; настройка размера часов меняет пропорцию.
- Шрифт, размер и цвет времени, даты, дня недели и текущей температуры.
- Независимые группы «Погодные условия», «Прогноз» и «Метеопоказатели»
  (ветер, направление, давление и влажность), общие для обоих макетов.
  Размер погодных условий задаётся для основной подписи («Малооблачно»);
  «Ощущается как» составляет 75% от него. В прогнозе размер задаётся для
  периода («Вечер», «Ночь»), температура — 105% этого размера. Шрифт и цвет
  применяются ко всем связанным строкам группы; текущая температура настраивается
  отдельно. Иконка текущей погоды масштабируется вместе с температурой; иконки
  прогноза — вместе с его размером, по центру высоты названия периода и температуры.
  Если строка не помещается в область погоды, она уменьшается целиком
  с сохранением пропорций, без обрезания текста.
  Пока доступны системные семейства без засечек, с засечками и моноширинное;
  точное начертание зависит от ОС. Размеры указаны для высоты 192 пикселя.
- Интенсивность тени, затемнение подложки от 0 до 100% и обводка текста.
- Выбор подложки: текущий градиент или изображения неба из `yandex-weather`.
- Логотип «Яндекс Погода» включается отдельным чекбоксом; по умолчанию скрыт.
  Красная «Я» сохраняет свой цвет, остальные буквы используют цвет текста погоды.
  SVG встроен локально и не требует загрузки из сети. В широком режиме логотип
  расположен справа вверху. В компактном режиме он плавно появляется справа
  внизу только на однострочном слайде метеопоказателей (ветер, давление, влажность),
  а при показе текущей погоды и прогноза скрыт.
  «Размер логотипа, px» задаёт его высоту (8–160, по умолчанию 16); ширина
  меняется пропорционально. Размер сохраняется в настройках и темах.
- «Защита от выгорания» плавно смещает часы, дату и погодные блоки по двум осям;
  логотип «Яндекс Погода» движется сильнее по горизонтали. Смещения ограничены
  свободным местом в области вывода. Дистанция и скорость настраиваются независимо
  уровнями 1–5: больший уровень увеличивает соответствующий параметр.
  Дистанции уровней: 1/2/3/4/6 пикселей при базовом масштабе макета; у логотипа
  горизонтальное смещение может быть до восьми раз больше, если есть место.
  Циклы скорости — примерно 24/16/10/6/3 минуты; у разных блоков и осей
  они немного различаются. Рекомендуемые значения: защита включена, дистанция 2, скорость 2.
  «Ускоренное демо (для превью)» ускоряет смещения в предпросмотре в 60 раз.
  Оно не влияет на реальный вывод, не сохраняется в настройках и темах
  и выключено при открытии страницы управления.
  Настройки входят в темы и сохраняются после перезапуска. В старых настройках
  отсутствующие параметры получают рекомендуемые значения.
  Смещения помогают распределить нагрузку на светодиоды, но не гарантируют
  отсутствие выгорания и не заменяют разумную настройку яркости.
- Включение погодных слайдов и длительность показа (3–120 секунд) в компактном режиме.

Автоматическое время суток учитывает положение солнца по координатам и текущему времени,
а также погодное состояние из сохранённого снимка: облачность, дождь, снег или грозу.
День, сумерки и ночь продолжают меняться даже при замороженном прогнозе. Если
координат нет, используется приближённое расписание в выбранном часовом поясе.
Можно выбрать время суток вручную. Подложка и слайды сменяются плавно.
В предпросмотре можно выбрать погодные условия вручную, чтобы проверить подложку
и текущую иконку. «Автоматически» берёт условия из текущего снимка. Этот выбор
не сохраняется в тему и не влияет на действующий вывод. Логотип «Яндекс Погода»
расположен поверх подложки и не меняет размеры погодных блоков.
Градиент остаётся вариантом по умолчанию, в том числе для сохранённых настроек.
Для подложки «Небо» в архив включены девять локальных изображений:
день, сумерки и ночь × ясное небо, переменная облачность и пасмурное небо.
Дождь, снег, град и гроза используют только пасмурный вариант `cloudy`,
без нарисованных поверх картинки осадков или молний. `clear` соответствует ясной
погоде, `partly-cloudy` — `partly`, `cloudy` и `overcast` — `cloudy`.
Для подложек используются только `day`, `dawn`, `night` × `clear`, `partly`, `cloudy`.
Сохранённое значение времени суток `dusk` совместимо с подложкой `dawn`.
Затемнение действует только на подложку; текст, температура и иконки сохраняют яркость.

На слайде подробностей ветер, направление, давление и влажность расположены в одну
строку. Вместо надписей «Ветер», «Давление», «Влажность» используются оригинальные
локальные SVG-иконки из `yandex-weather`; для направления ветра есть поворотная
стрелка, при штиле она скрыта. Давление указано в мм рт.ст. Показатели без данных
пропускаются. Изображения, иконки и выбор подложки автономны и не обращаются к CDN.
Классами подложки управляет JS, а картинки выбирает CSS (`photo day clear`,
`photo night cloudy` и аналогичные сочетания). Исходные материалы перенесены из
`yandex-weather`; его лицензионный текст сохранён в `public/assets/LICENSE-yandex-weather.txt`.

## Темы и перенос настроек

В разделе «Темы» можно сохранить все текущие параметры под именем: компоновку,
часы и дату, оформление, шрифты и размеры, анимацию и настройки погодных слайдов.
Сохраняются и ещё не применённые значения из формы. Каталог из максимум 50 тем
хранится в локальном постоянном хранилище плагина на устройстве GMIB, вместе
с текущими настройками; он доступен после перезапуска и из другого браузера
управления тем же устройством. Название — до 80 символов. Повторное сохранение
с тем же названием заменяет тему.

«Загрузить» заполняет настройки и обновляет предпросмотр. Чтобы применить их
к действующему экрану, нажмите «Применить». Удаление темы не меняет
текущие параметры экрана.

«Экспорт JSON» скачивает текущие параметры из формы с указанным названием.
На другом устройстве выберите этот файл в «Импорт темы из JSON»: тема сохранится
в каталоге и загрузится в предпросмотр. Импорт с существующим названием заменяет
тему. Некорректный файл не меняет тему и текущие параметры. Файл содержит формат
`gmib-informer-theme`, версию `1`, название и проверенные настройки. Допустимый
размер файла — 512 КБ. Фактическая погода, API-ключи, идентификаторы экранов и
запуск вывода не переносятся. Подложки уже включены в плагин; системные шрифты
на разных устройствах могут выглядеть по-разному.

## Источник погоды и кеш

В разделе «Источник погоды» задайте широту и долготу в одной строке и нажмите
«Добавить ключ». Можно добавить до **10 ключей**. Для каждого задаются название,
секретный ключ, суточный лимит и тип: «Автоматически», «Умный дом» или «Для сайта».
Пустые строки заранее не создаются; у каждого добавленного ключа есть кнопка удаления.
Изменения применяются общей кнопкой «Применить».

Поддерживаются два API Яндекса с адаптацией ответа в общий формат:

- «Умный дом» — `/v2/forecast`, в том числе `forecasts[].parts` с именованными
  периодами. Для бесплатного ключа укажите лимит 30.
- «Для сайта» — `/v2/informers`, прогноз в `forecast.parts`. Для старого бесплатного
  тарифа укажите лимит 50.

В автоматическом режиме лимит 30 предполагает «Умный дом», а 50 — «Для сайта».
Для остальных лимитов первым проверяется `/v2/forecast`. Первый успешный ответ
подтверждает рабочий API; результат сохраняется для последующих запросов. При
HTTP 403 или 404 проверяется другой URL: не более двух обращений при одном
определении. В тестовом режиме проверки API не выполняются. Определяется рабочий
URL, а не тариф или реальная квота провайдера; лимит задаётся вручную.

Ошибочный формат или отклонённый API ключ выделяется серым, его можно заменить
либо удалить. Если ключей нет, «Использовать последний ответ» включено и недоступно
для снятия. Новый ключ вводится в пустое поле; пустое поле существующего ключа
сохраняет прежнее значение.

По умолчанию включено «Использовать последний ответ»: плагин показывает текущий
тестовый JSON для координат 56.6333, 47.8908 без обращения к Яндексу. При каждом
успешном реальном запросе последний ответ заменяется новыми проверенными данными.
Он сохраняется в хранилище GMIB, поэтому доступен после перезапуска и обновления
плагина. Импорта снимков и отдельной кнопки однократной загрузки больше нет.

Пока флаг включён, в правом верхнем углу вывода показана цветная надпись
«Тестовый вывод» поверх картинки. После отключения флага и применения настроек
плагин начинает автоматическое обновление. Уже отправленный запрос может завершиться
перед применением флага; новых запросов в этом режиме нет.

Запросы выполняет единственный планировщик backend независимо от числа открытых
экранов и страниц настроек. После запроса он складывает доступные остатки ключей и распределяет общий пул
равномерно по времени до следующей полуночи по Москве. Для очередного обращения
выбирается ключ с наибольшей долей оставшегося бюджета. Минимальный интервал —
минута. Если бюджет исчерпан, обновления ждут сброса. После выключения компьютера
пропущенные обновления не наверстываются: при запуске новый суточный бюджет
распределяется по оставшейся части дня. Вчерашний расход сбрасывается и тогда,
когда компьютер был выключен в момент полуночи.

Для каждого ключа видны расход квоты за сегодня, её остаток, общий счётчик попыток,
тип рабочего API и результат последнего обращения. Сводка показывает доступный пул,
расход квоты, общее число попыток, время следующего обновления и сброса.

Перед отправкой попытка записывается в хранилище. **HTTP 403 и 404 не расходуют
квоту**: резерв возвращается, однако само обращение остаётся в общем счётчике.
Ошибки сети, некорректные ответы и остальные HTTP-ошибки учитываются в расходе
консервативно. Незавершённая при выключении попытка также сохраняет резерв.
Удаление и повторное добавление того же секрета, перестановка или переименование
строк и перезапуск не обнуляют его счётчики. При замене секрета используется учёт
нового ключа, а общий счётчик установки сохраняет историю прежних обращений.

После ошибки сохраняется последняя успешная погода. HTTP 401, 403, 404 или 429
приостанавливают только соответствующий ключ до сброса суток (для неизвестного
типа сначала выполняется описанная проверка второго URL). Остальные ключи продолжают
обслуживать общий пул. Остаток квоты заблокированного ключа показывается отдельно,
но временно не входит в доступный для планировщика пул.

Счётчик отражает запросы **этой установки Informer**. Вызовы того же ключа другими
программами или устройствами в него не входят. Укажите бюджет с учётом таких вызовов;
для нескольких установок разделите общий лимит между ними. Несколько ключей
одного тарифа могут иметь общую квоту: распределите её между строками, чтобы
общий пул не учитывал один и тот же лимит несколько раз.

Ключи сохраняются локально в хранилище GMIB, передаются Яндексу только в заголовке,
не возвращаются в состояние, предпросмотр, realtime или темы. Пустое поле при
повторном применении сохраняет прежний ключ. Координаты, бюджет и режим источника
также не входят в темы. Хранилище плагина — `informer.v1`; в установочном архиве
персональных ключей и текущих счётчиков нет.

Прогноз на экране показывает два ближайших будущих периода по часовому поясу
часов: ночью — утро и день, утром — день и вечер, днём — вечер и следующую ночь,
вечером — следующую ночь и утро. Границы периодов: 00:00, 06:00, 12:00, 18:00.
Текущий и прошедшие периоды исключаются; выбор меняется автоматически, без нового
запроса погоды. Если будущих данных в кеше недостаточно, показываются только
доступные периоды, без повторения старого прогноза.

Текущая погода и прогноз используют код иконки из ответа Яндекса как для API,
так и для сайта. Если изображение недоступно, показывается встроенная иконка
по состоянию погоды. Само состояние и выбор подложки от кода иконки не зависят.

## Погода со страницы Яндекса без ключа

Включите «Обновлять со страницы Яндекса» и вручную укажите URL города, например
`https://yandex.ru/pogoda/ru/yoshkar-ola`. Широта и долгота в запросе всегда берутся
из общих полей координат; параметры и фрагмент введённого URL отбрасываются.
Поддерживаются только HTTPS-страницы городов на `yandex.ru` и `www.yandex.ru`.

Предпочтительный интервал задаётся в минутах: от 5 до 1440, по умолчанию 15.
API продолжает работать по своему расписанию и квотам, а страница дополняет
обновления между запросами API. Успешный ответ API откладывает следующее обновление
страницы на выбранный интервал. Без API-ключей страница работает самостоятельно;
при заполненном адресе можно снять «Использовать последний ответ». Эта галочка
останавливает оба источника и включает надпись «Тестовый вывод» на экране.

При первом обновлении загружается HTML с текущей погодой, прогнозом и кодом иконки.
Из публичного JavaScript сайта определяется идентификатор лёгкого фонового запроса;
скрипт читается как текст и не исполняется. Идентификатор сохраняется локально.
Последующие обновления выполняются небольшим POST-запросом на ту же страницу,
без повторной загрузки HTML, cookies, авторизации и погодного API-ключа.
Если идентификатор не найден, используется разбор полной страницы. После обновления
парсера старый кеш пересчитывается из полного HTML при ближайшем плановом запросе,
без ожидания суток. Тестовый режим и паузы после ошибок при этом сохраняются.

Лёгкий ответ обновляет температуру, ветер, давление, состояние и иконку. Прогноз,
ощущаемая температура, влажность и направление ветра сохраняются из предыдущего
ответа для тех же координат, если в лёгком ответе их нет. Для обновления прогноза
и сведений о версии сайта полный HTML запрашивается раз в сутки.
Прогнозы API и сайта кешируются независимо. При наличии API-ключей данные API
имеют приоритет для совпадающих даты и периода. Недостающие периоды берутся с сайта:
например, если API содержит только день и вечер, следующая ночь берётся из прогноза
сайта. Лёгкие запросы обновляют текущую погоду, сохраняя оба прогноза. Кеши сохраняются
при перезапуске. После удаления ключей, смены координат или
истечения дат прогноза используется прогноз сайта. Для сайта диапазоны частей
суток вычисляются по почасовым температурам, только если есть все шесть часов
периода: ночь 00–05, утро 06–11, день 12–17, вечер 18–23 по времени страницы.
Ночной блок карточки сайта относится к следующей календарной дате: ночь в карточке
«30 октября» — это 31 октября, 00–05. Значок и состояние берутся из этого же блока,
а диапазон температур — из часов соответствующей ночи. Иконки CSS-атласа сайта
сопоставляются с цветными SVG Яндекса; при обновлении парсера старый кеш пересобирается
из полной страницы во время ближайшего планового запроса.
Если часов недостаточно, остаётся одиночная температура из карточки сайта. Смена координат
не переносит дополнительные показатели от прежнего места. Иконка берётся по коду
Яндекса; если изображение недоступно, используется встроенная иконка.

Обновления сайта имеют отдельные суточный и общий счётчики и не расходуют пул
API-запросов. Одновременные страницы управления и экраны не создают отдельных
планировщиков. Кеш и расписание переживают перезапуск; пропущенные запросы
не наверстываются серией обращений. Для полной страницы поддерживаются ETag,
Last-Modified и ответ 304, когда их предоставляет сервер.

Защита от слишком частых неудачных обращений:

- при HTTP 429 учитывается `Retry-After`, а при сетевых и серверных ошибках
  интервал повторов увеличивается;
- HTTP 403 или страница проверки доступа приостанавливают обновления сайта;
  после устранения причины можно нажать «Возобновить»;
- если HTML или лёгкий ответ больше не содержат корректных данных ожидаемого
  назначения, погода сохраняется из кеша, а следующая проверка выполняется только
  через 24 часа. Такая пауза сохраняется после перезапуска и смены интервала.

Парсер ищет данные по смысловым признакам и проверяет значения, а не исполняет
код страницы. Формат сайта является внутренним и может меняться; автоматическая
проверка раз в сутки позволяет восстановить работу после изменения версии сайта,
если данные по-прежнему доступны. «Возобновить» разрешает явную ручную проверку
раньше срока с соблюдением обычного интервала. Паузы сайта не останавливают API.

Backend использует существующий Plugin API 1.1. HTTP-маршруты локальные.
NiBUS и дополнительные погодные провайдеры остаются следующими этапами.

## Проверка и сборка

```sh
node --test tests/informer*.test.mjs
pnpm validate
pnpm build --plugin informer
```

Команды выполняются из корня репозитория. Архив: `dist/informer.gmib-plugin`.
Тесты проверяют валидацию и миграцию оформления, независимые настройки прогноза
и метеопоказателей, кеш, суточный бюджет, смену московских суток, паузу и
возобновление запросов, ошибки провайдера/хранилища, отсутствие ключа в публичном
состоянии и перезапуск.
Предпросмотр в браузере проверяет макеты; фактическое расположение окон и
читаемость на LED следует проверять на настроенной установке GMIB.

## Приложение настроек на рабочем столе

Откройте страницу настроек Informer на localhost в Chrome или Edge. Нажмите
«Установить приложение», если браузер показывает эту кнопку, либо выберите установку
в меню браузера. Ярлык открывает настройки в отдельном окне.

После первого открытия при работающем GMIB оболочка настроек сохраняется локально.
Если GMIB закрыт, приложение показывает «Запустите GMIB» и автоматически
восстанавливает связь после его запуска. Данные API не кешируются этим приложением:
для чтения и применения настроек GMIB должен работать.

Кнопка «Применить» сохраняет настройки и показывает уведомление «Настройки применены»
после подтверждения от GMIB. При ошибке появляется сообщение с её причиной.

## Переключение вывода и рекламный плеер

Во вкладке «Вывод» выберите два разных уже настроенных экрана GMIB. «Показать»
включает выбранный режим, «Скрыть» выключает вывод Informer, «Переключить» меняет
широкий режим на компактный и обратно. Если хост предоставляет `output.applyLayout`,
прежний вывод остаётся впереди до готовности нового экрана и первого кадра рекламного
плеера (ожидание до 8 секунд); затем хост убирает прежний экран. Если кадр не появился,
прежний вывод сохраняется и пульт сообщает об ошибке. На хостах без этого метода используется
прежнее последовательное переключение с предварительным скрытием экрана.
Другие плагины не отключаются. Главное окно GMIB остаётся скрытым или свёрнутым.

Галочка «Управлять плеером» и список плееров связывают вывод с рекламой. В компактном
режиме выбранный плеер открывается скрытым, начинает воспроизведение и показывает
настроенные окна рекламы. В широком режиме и по команде «Скрыть» плеер останавливается,
его вывод скрывается. Плейлист и геометрию рекламы предварительно настройте в GMIB.
При ошибке согласованного переключения хост сам восстанавливает прежний вывод,
а Informer сообщает причину. Если переключение удалось, но настройки не сохранились,
Informer возвращает предыдущий экран и состояния плееров. На хостах без `applyLayout`
прежний вывод восстанавливается последовательными командами.

Настройки вывода сохраняются при выполнении команды, отдельно от темы оформления.
При автозапуске восстанавливаются выбранный экран и связанное состояние плеера.
Для управления плеером требуется отдельное разрешение `player.control`; новый архив
Informer требует Plugin API 1.2, поэтому сначала обновите GMIB до 5.7.1.
Сведения о методах хоста — в [Plugin API 1.2](../../docs/plugin-output-api.md).

### HTTP-команды вывода

`GET /plugins/informer/api/output` возвращает `screens`, `status`, `config`, `players`
и `features.playerControl`. Метаданные плееров доступны только через разрешённое API
хоста. Отсутствующие методы старого хоста не вызываются.

`PUT /plugins/informer/api/output` принимает `{ command, config }`. Команды:
`show`, `hide`, `toggle` (а также `configure` для сохранения без запуска).
`config` содержит `wideScreenId`, `compactScreenId`, `mode` (`wide`/`compact`),
`autoStart`, `playerEnabled`, `playerId`. Для `hide` используется сохранённая привязка;
даже некорректный незавершённый ввод не мешает скрыть текущий вывод.
Команды сериализуются с сохранением настроек и другими операциями плагина.

Ответ содержит актуальное состояние в том же формате, что GET. Ошибки: 422 для
неверной конфигурации, 409 для отсутствующих возможностей хоста, 503 для неактивного
экрана и 500 для ошибки исполнения/восстановления. Клиент не должен считать команду
успешной при ошибке HTTP или `status.active: false` после `show`/`toggle`.
Старое тело `{screenId,pageId:"screen",autoStart}` и `DELETE /output` поддерживаются.
HTTP-маршруты остаются локальными согласно политике доступа плагина.
