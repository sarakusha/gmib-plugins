# Informer — часы, дата и погода

Первый прототип для GMIB Plugin API 1.1: часы и погодные слайды с сохранённым
ответом Яндекс Погоды. Плагин автономен: внешние шрифты, картинки и CDN не нужны.
Рабочее название — Informer; общий план развития: [informer-plan.md](../../docs/informer-plan.md).

## Запуск

1. Установите `informer.gmib-plugin` через раздел «Плагины» GMIB и перезапустите GMIB.
2. Откройте настройки Informer. В «Вывод» выберите уже настроенный экран GMIB
   и нажмите «Назначить и запустить». При необходимости включите автозапуск.
3. Для Волгатех используйте 704×192, для часов рядом с рекламой — 320×192.
   Геометрию экранов и отдельного рекламного плеера настраивайте в GMIB.
4. Выберите группу настроек слева: показываются только её поля и общий предпросмотр.
   После настройки нажмите «Сохранить настройки».

Предпросмотр получает реальные размеры экранов GMIB. Если экранов несколько,
выберите нужный в списке над предпросмотром; при одном экране он выбирается автоматически.
Выбор здесь не запускает и не переназначает вывод. Изменение размеров в GMIB
подхватывается автоматически. При отсутствии экранов сначала добавьте экран в GMIB.

В автоматическом макете широкое табло разделяется на область часов (по умолчанию
320 пикселей) и погоду справа. В компактном макете погода сменяется под часами.
Плагин сам не управляет рекламным плеером и не меняет его размеры.

Часы и дата центрируются в области часов. Часы прижаты к двоеточию справа,
минуты — слева; положение разделителя не меняется вместе с цифрами. Без секунд
двоеточие мигает с периодом в одну секунду.

## Настройки

- Ширина области часов, автоматический/широкий/компактный макет.
- Секунды, локаль и часовой пояс.
- «Дата и время»: в одной строке — «Четверг, 15 июля, 10:12»; в отдельных
  строках — дата сверху, крупные часы снизу. День недели и год не создают
  дополнительных строк.
- Формат даты задаётся отдельными списками: день недели, день, месяц, год и эра.
  Любое поле можно отключить. Если отключены все поля, остаётся только время.
  Названия и порядок компонентов даты зависят от локали; JSON вводить не нужно.
  Старые сохранённые настройки поддерживаются, прежний `dateStyle` раскрывается
  в отдельные поля при открытии настроек.
- В одной строке размер времени связан с размером даты (при стандартном размере
  часов 80 он равен размеру даты). Длинная строка целиком уменьшается до ширины
  области, сохраняя все включённые поля; настройка размера часов меняет пропорцию.
- Шрифт, размер и цвет времени, даты, дня недели, температуры и погодных подписей.
  Пока доступны системные семейства без засечек, с засечками и моноширинное;
  точное начертание зависит от ОС. Размеры указаны для высоты 192 пикселя.
- Интенсивность тени, затемнение подложки от 0 до 100% и обводка текста.
- Выбор подложки: текущий градиент или изображения неба из `yandex-weather`.
- Надпись «Яндекс Погода» включается отдельным чекбоксом; по умолчанию скрыта.
- Включение погодных слайдов и длительность показа (3–120 секунд).

Автоматическое время суток учитывает положение солнца по координатам и текущему времени,
а также погодное состояние из сохранённого снимка: облачность, дождь, снег или грозу.
День, сумерки и ночь продолжают меняться даже при замороженном прогнозе. Если
координат нет, используется приближённое расписание в выбранном часовом поясе.
Можно выбрать время суток вручную. Подложка и слайды сменяются плавно.
Градиент остаётся вариантом по умолчанию, в том числе для сохранённых настроек.
Для подложки «Небо из yandex-weather» в архив включены девять локальных изображений:
день, сумерки и ночь × ясное небо, переменная облачность и пасмурное небо.
Дождь, снег и гроза используют пасмурный вариант с дополнительным погодным слоем.
Затемнение действует только на подложку; текст, температура и иконки сохраняют яркость.

На слайде подробностей ветер, направление, давление и влажность расположены в одну
строку. Вместо надписей «Ветер», «Давление», «Влажность» используются оригинальные
локальные SVG-иконки из `yandex-weather`; для направления ветра есть поворотная
стрелка, при штиле она скрыта. Давление указано в мм рт.ст. Показатели без данных
пропускаются. Изображения, иконки и выбор подложки автономны и не обращаются к CDN.
Классами подложки управляет JS, а картинки выбирает CSS (`photo day clear`,
`photo night rain` и аналогичные сочетания). Исходные материалы перенесены из
`yandex-weather`; его лицензионный текст сохранён в `public/assets/LICENSE-yandex-weather.txt`.

## Погода без фоновых запросов

В комплекте снимок для координат 56.6333, 47.8908, полученный одним запросом
29 октября 2026 года. Это демонстрационные сохранённые данные, **не живая погода**.
Происхождение и время наблюдения снимка указаны в настройках. Нижняя строка
с пометкой «Демо» и временем снимка на экран не выводится; прогноз содержит даты.
Часы всегда показывают текущее время.

Доступны два способа сменить снимок:

- «Импорт ответа Яндекс Погоды v2» — вставить JSON Informers или Forecast.
  Импорт не делает сетевых запросов и сохраняет только известные погодные поля.
- «Получить прогноз один раз» — ввести ключ **Informers v2** и координаты.
  Используется `/v2/informers`, другие типы ключей могут не подойти.
  Попытка отмечается в постоянном хранилище **до** отправки. После ошибки,
  перезапуска или переустановки автоматического повтора нет. При неудаче
  остаётся предыдущий прогноз; для замены можно использовать импорт JSON.

Ключ передаётся в заголовке запроса провайдеру, не сохраняется, не возвращается
в состояние, не попадает в realtime и установочный архив. После запроса поле
очищается. На этой стадии ввод ключа не включает регулярное обновление.

Настройки и кеш лежат в хранилище GMIB отдельно от файлов плагина, ключ `informer.v1`.
Они переживают перезапуск и обновление/переустановку. В первом прототипе один общий
профиль настроек; оба целевых размера используют его. Погодные поля без данных
скрываются, нулевые значения сохраняются.

## Разрешения и совместимость

`http.routes`, `storage`, `realtime`, `output.pages`, `output.control` нужны для
настроек, сохранённого прогноза, обновления интерфейса и выбора существующего
вывода. NiBUS и запись на шину не запрашиваются. Backend работает на существующем
Plugin API 1.1; изменения самого GMIB для этого прототипа не требуются.
HTTP-маршруты локальные, отдельного удалённого API управления пока нет.

Автоматическое обновление с учётом суточной квоты, постоянное защищённое хранение
ключей, дополнительные провайдеры и температура NiBUS — следующие этапы.
Бесплатные тарифы имеют условия применения: тариф Яндекса для умного дома
не следует автоматически считать подходящим для табло организации с рекламой.

## Проверка и сборка

```sh
node --test tests/informer.test.mjs
pnpm validate
pnpm build --plugin informer
```

Команды выполняются из корня репозитория. Архив: `dist/informer.gmib-plugin`.
Тесты проверяют валидацию, кеш, однократный запрос, параллельные обращения,
ошибки провайдера/хранилища, отсутствие ключа в сохраняемых данных и перезапуск.
Предпросмотр в браузере проверяет макеты; фактическое расположение окон и
читаемость на LED следует проверять на настроенной установке GMIB.
