# KeUSB-24R

Локальный экспериментальный плагин GMIB для управления четырьмя релейными выходами KeUSB-24R.
Основной сценарий — освещение по времени и показаниям датчика. Не опубликован в каталоге.
Требуется экспериментальное расширение Plugin API 1.3 с `serial` и `environment`;
обычная установленная версия GMIB без этого расширения не поддерживается.

## Управление

В GMIB откройте «Плагины → KeUSB-24R → Управление».

- **Совместно** — команда для указанного выхода отправляется всем подключённым устройствам.
  Если состояния различаются, показано «Разные». Нажатие включает этот выход на всех устройствах.
- **По отдельности** — выбор устройства через селектор и управление четырьмя выходами.
- Состояние показано по ответам устройства, без предварительного переключения интерфейса.
  «Нет данных» блокирует ручное управление. Потеря связи с GMIB блокирует все изменения.
- Выбор режима относится к ручному управлению: каждое задание сохраняет собственную цель,
  «Все устройства» или конкретный аппаратный идентификатор. Переключение режима не меняет задания.

Устройство определяется по USB VID/PID и проверке протокола, индивидуальная привязка — по ответу
`$KE,SER`. Одинаковые аппаратные идентификаторы не допускаются. После отключения запись остаётся
в списке, состояние помечается неизвестным. Команды для отключённых устройств не ставятся в очередь.

## Автоматизация

Во вкладке «Автоматизация» можно добавить, изменить, удалить и приостановить задание.
Каждый выход имеет независимое действие: включить, выключить или не менять.

**Расписание:** один раз в выбранную дату либо ежедневно; точное время или событие
«Восход», «Начало дня», «Заход», «Начало ночи» со смещением в минутах.
Часовой пояс, солнечные события и координаты задаются централизованно в GMIB.
Положительное смещение — после события, отрицательное — перед ним.
Пропущенные во время остановки GMIB задания не выполняются задним числом.

**Освещённость:** выбор датчика GMIB, условие меньше порога, диапазон или больше порога,
действия для одного или нескольких выходов. Гистерезис защищает от частого переключения около
границы. Хост исключает устаревшие показания (порог 60 секунд); ядро автоматизации дополнительно
отклоняет данные старше 120 секунд. Правило срабатывает при входе в условие;
для обратного действия создайте отдельное условие. После запуска плагина правило может
сработать, если текущие свежие показания уже соответствуют условию.

Ручное переключение не отключает автоматизацию: его может изменить следующее задание или
следующий вход в условие освещённости. Для длительного ручного управления приостановите
соответствующие задания и условия. При совпадающих действиях нескольких правил итог зависит
от порядка их выполнения; избегайте пересекающихся правил с противоположными действиями.

## Журнал и хранение

Журнал доступен на отдельной вкладке, фильтруется по устройству. Хранятся изменения, подключения
и ошибки за последние 7 дней, максимум 10 000 событий. Данные и задания сохраняются в хранилище
плагина GMIB, отдельно от файлов плагина. Перезапуск и обновление архива не удаляют задания.

## PWA

Страница содержит manifest и service worker; в поддерживаемом браузере доступна кнопка
«Установить» или установка через меню браузера. Service worker работает только в безопасном
контексте (HTTPS или localhost). На обычном HTTP по IP-адресу страница остаётся веб-интерфейсом.
Кешируется только оболочка страницы; состояние устройств, команды и авторизация не кешируются.
Без связи состояние не считается актуальным, команды недоступны и не откладываются на потом.

Страница использует локальные маршруты `api/…`, как существующие плагины GMIB. При работе
через удалённое подключение настольного GMIB его штатный локальный прокси выполняет авторизацию
на удалённом хосте. PWA устанавливается с localhost. Прямой доступ с телефона по LAN требует
отдельной интеграции HTTPS и авторизации хоста; в этой версии она не добавлена. Backend также
регистрирует authenticated API для штатных авторизованных клиентов GMIB. Пароль или токен
в URL страницы не передаются.

## Совместимость и проверка

- Протокол: руководство Ke-USB24R v1.07; чтение выходов требует соответствующей прошивки
  устройства (команды состояния документированы для firmware 2.0 и новее).
- Serial transport рассчитан на Windows, macOS и Linux через API хоста; установленные драйверы
  и доступ к порту обязательны. Linux может требовать членство в группе доступа к serial.
- Скорость порта 9600 — первоначальная настройка транспорта, требует проверки на оборудовании:
  руководство не задаёт baud rate виртуального COM-порта явно.
- USB-патч детектора NiBUS не является зависимостью плагина: плагин использует отдельный serial API.
- Температурные сценарии, импульсные выходы и изменение направления GPIO пока не реализованы.

Из корня `gmib-plugins`: `pnpm validate`, `pnpm build`. Архив создаётся в `dist`.
При проверке интерфейса использовался локальный стенд с имитацией двух реле: состояния,
смешанное состояние группы, редактор lux-условия и отправка нескольких действий; проверены
компоновки desktop и 390px. Реальные реле, PWA на телефоне и три ОС требуют отдельного испытания.

Проверка подключённого модуля на macOS: при 9600 baud получены ответы
`#FW,2.0` и `#RDR,ALL,0,0,0,0`. Команды переключения не отправлялись.
Windows/Linux и управление физической нагрузкой требуют отдельной проверки.

Планировщик предлагает все точки автояркости GMIB: Рассвет, Восход, Утро, День,
Зенит, Вечер, Закат, Сумерки, Ночь, Надир. Смещение применяется к выбранной точке.
Сохранённые задания «Начало дня» и «Начало ночи» открываются как «День» и «Ночь»
без изменения момента исполнения. Если хост не предоставил время события
(например, при полярном дне), задание не исполняется.
Для новых точек требуется обновлённый хост GMIB и перезапуск dev. На старом хосте
неподдерживаемые точки недоступны; ранее сохранённые задания продолжают работать.

На главной странице показано число подключённых модулей реле (не выходов).
При отсутствии связи число не показывается как актуальное. Во время команды
переключатели временно блокируются, а статус сообщает о выполнении.
